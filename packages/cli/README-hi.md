# jevcore-cli

`jev` कमांड लाइन: शेल, स्क्रिप्ट या CI जॉब से TypeSafe [Jev](https://typesafe.ai)
के निर्णय।

यह पैकेज उसी निर्णय-कोर का चौथा प्रवेश द्वार है जिस पर लाइब्रेरी, MCP सर्वर और
DeepSeek Harness प्लगइन टिके हैं। यहाँ कोई भी निर्णय दोबारा लागू नहीं किया गया है:

- `jev ask` `JevService.ask` को कॉल करता है, इसलिए एग्रेस अनुबंध और रिडैक्शन पथ
  सत्र की तरह ही लागू होते हैं;
- `jev check` `resolveCheck` को कॉल करता है, वही रिज़ॉल्वर जो MCP टूल इस्तेमाल करता है;
- `jev gate` `createSafetyGate` को कॉल करता है, वही फ़ंक्शन जो harness रजिस्टर करता है;
- `jev egress` `EgressContract.reportLines` को कॉल करता है, यानी अनुबंध का आत्म-विवरण।

इसलिए प्रॉम्प्ट पर लिया गया निर्णय वही अर्थ रखता है जो किसी एजेंट के भीतर लिया गया
निर्णय रखता है।

## इंस्टॉल

```sh
npm install -g jevcore-cli
```

ऑफ़लाइन mock प्रोवाइडर डिफ़ॉल्ट है और उसे किसी और चीज़ की ज़रूरत नहीं। लाइव रूट के
लिए `@typesafe-ai/sdk` चाहिए, जो कोर का वैकल्पिक डिपेंडेंसी है।

## कमांड

| कमांड | क्या बताता है |
|---|---|
| `jev ask` | एक state पर टाइप्ड सवालों का एक बैच — noul, choice, score |
| `jev check` | साक्ष्य के आधार पर किसी claim के लिए छह में से एक निर्णय, और साथ में प्रायिकताएँ |
| `jev rank` | प्रासंगिकता के क्रम में उम्मीदवार, हर एक के लिए एक प्रायिकता |
| `jev gate` | किसी टूल कॉल पर सुरक्षा गेट क्या तय करेगा, उसे चलाए बिना |
| `jev egress` | यह टूल क्या भेज सकता है, और हर फ़ील्ड की सीमा |
| `jev models` | हर रूट कौन-सा मॉडल और endpoint इस्तेमाल करेगा |

हर कमांड `--json` के साथ मशीन-पठनीय आउटपुट देता है और डिफ़ॉल्ट रूप से मनुष्य के
पढ़ने योग्य रूप छापता है। `data` के नीचे के फ़ील्ड नाम स्थिर हैं, ठीक वैसे ही जैसे
एग्ज़िट कोड स्थिर हैं।

## सवाल पूछना

```sh
jev ask --state record.json --questions questions.json --feature tool:jev_ask
```

```json
{
  "usable": {
    "type": "noul",
    "instructions": "Is this record usable?",
    "boundary": { "true": "it can be used as it stands", "false": "it cannot" }
  }
}
```

`--feature` चुनता है कि यह कॉल किस एग्रेस फ़ीचर के अंतर्गत जाएगी। यह घोषित फ़ीचरों
में से एक होना चाहिए, और बिना घोषित नाम कठोर त्रुटि देता है और उनकी सूची दिखाता है —
क्योंकि यह तय करता है अनुबंध, कमांड लाइन नहीं, कि मशीन से बाहर क्या जा सकता है।

## किसी claim की जाँच

```sh
jev check --claim "the build is reproducible" --evidence build.log
```

```
claim: the build is reproducible
evidence: 4821 chars — "commit 3f9a1c2 ..."
verdict: supported  (supports=0.95 contradicts=0.05 sufficient=0.90)
```

निर्णय छह शब्दों में से एक है, और ये दो शब्द चार पर्यायवाची नहीं हैं:

| निर्णय | अर्थ |
|---|---|
| `supported` | साक्ष्य claim का समर्थन करता है और पर्याप्त पाया गया |
| `contradicted` | साक्ष्य claim का खंडन करता है |
| `conflicted` | साक्ष्य claim का समर्थन भी करता है और खंडन भी |
| `insufficient` | साक्ष्य claim को सिद्ध नहीं करता |
| `undecided` | साक्ष्य प्रश्न तय कर देता है पर किसी ओर इंगित नहीं करता |
| `unknown` | कोई माप ही वापस नहीं आया |

## एग्ज़िट कोड

| कोड | अर्थ |
|---|---|
| `0` | `check` ने claim का समर्थन किया; `gate` ने कॉल की अनुमति दी; कमांड ने आउटपुट दिया |
| `1` | `check` ने claim का खंडन किया; `gate` ने कॉल अस्वीकार की; इनपुट त्रुटि |
| `2` | `gate` आगे बढ़ने से पहले किसी मनुष्य से पूछेगा |
| `3` | `check` ने `conflicted`, `insufficient`, `undecided` या `unknown` लौटाया |
| `64` | कमांड लाइन ही ग़लत है |

एग्ज़िट कोड `3` इसलिए है क्योंकि आख़िरी चार निर्णय *साक्ष्य* के बारे में निष्कर्ष हैं,
claim के बारे में नहीं। जो स्क्रिप्ट इन्हें "समर्थन नहीं" पढ़े, वह ऐसे खंडन की रिपोर्ट
कर रही होगी जिसे किसी ने मापा ही नहीं; और CI में यही अंतर है "यह claim ग़लत है" और
"यह रिपॉज़िटरी बता ही नहीं सकती" के बीच।

## गेट, बिना चलाए

```sh
jev gate --tool git --args-json '{"command":"push --force"}' --severity-block high
```

```
jev gate git
decision: ask  severity: high  (blocks at high)  exit: 1
  RAISED  external_side_effect
reason: jevcore safety gate: Jev flagged external_side_effect; the severity "high" is at or above the "high" block level.
nothing was executed: this is a dry run, and the arguments above are data.
```

यही वह कमांड है जिसे जानना काम का है। सत्र में गेट डिफ़ॉल्ट रूप से बंद रहता है और
उसका काम यह है कि जब तक कुछ ख़तरनाक न हो, वह अदृश्य रहे — इसलिए कोई ख़तरनाक टूल कॉल
तैयार किए बिना यह पूछने का रास्ता नहीं था कि वह क्या करेगा। यहाँ टूल का नाम और उसके
आर्ग्युमेंट सिर्फ़ **डेटा** हैं: कोई टूल नहीं बुलाया जाता, कोई फ़ाइल नहीं छुई जाती,
कोई प्रक्रिया शुरू नहीं होती।

निर्णय `createSafetyGate` से आता है, इसलिए यह वही निर्णय है जो किसी सत्र को मिलता।
यह जिन ख़तरों का आकलन करता है वे कोर में घोषित हैं और `jev egress --feature gate:safety`
उन्हें छापता है: अपरिवर्तनीय विनाश, विशेषाधिकार वृद्धि, क्रेडेंशियल का खुलासा, बाहरी
दुष्प्रभाव, और इतिहास का पुनर्लेखन, साथ में एक गंभीरता स्कोर।

## मशीन से बाहर क्या जा सकता है

```sh
jev egress
```

```
provider: mock  endpoint: none  transmitting: no
[jevcore] provider=mock  endpoint=none  egress=OFF  (no network calls will be made; every answer is synthetic)
ARMED  gate:safety
         state <= 8000 chars - the tool name, its arguments, and the session working directory
         questions <= 2000 chars - the fixed hazard questions
```

`EgressContract` वह एकमात्र जगह है जो तय करती है कि मशीन से बाहर क्या जा सकता है। हर
फ़ीचर घोषित करता है कि वह कौन-से फ़ील्ड भेजेगा और हर एक की सीमा क्या है, अनुबंध स्वयं
का वर्णन कर सकता है, और यह कमांड वही वर्णन उस रूप में छापता है जो उस इनवोकेशन पर लागू
होता है जिसे आप चलाने वाले हैं।

दोनों रूट **डिफ़ॉल्ट रूप से बंद** हैं। `--provider live` और `--provider openrouter`
भेजते हैं; बाक़ी सब कुछ ऑफ़लाइन mock पर चलता है, जो इनपुट के हैश से उत्तर देता है,
कोई सॉकेट नहीं खोलता, और हर परिणाम को stderr के साथ-साथ पेलोड में भी सिंथेटिक बताता है।

रिडैक्शन हर उस चीज़ पर चलता है जो बाहर जाती है, और उसकी सीमा छिपाई नहीं जाती बल्कि
लिखी जाती है: यह पहचाने गए फ़ील्ड नामों के मान और ज्ञात सीक्रेट आकारों से मेल खाती
स्ट्रिंग हटा देता है, पर मुक्त टेक्स्ट में लिखे किसी अनजाने सीक्रेट को नहीं पहचान सकता।

## कॉन्फ़िगरेशन

| वेरिएबल | असर |
|---|---|
| `TYPESAFE_API_KEY` | `live` प्रोवाइडर के लिए क्रेडेंशियल |
| `OPENROUTER_API_KEY` | `openrouter` प्रोवाइडर के लिए क्रेडेंशियल |
| `JEV_PROVIDER` | `--provider` का डिफ़ॉल्ट |
| `TYPESAFE_BASE_URL` | `live` रूट पर `--endpoint` का डिफ़ॉल्ट |
| `OPENROUTER_BASE_URL` | `openrouter` रूट पर `--endpoint` का डिफ़ॉल्ट |

क्रेडेंशियल कभी छापा, लॉग या प्रतिध्वनित नहीं जाता। टूल बस यह बताता है कि कोई कुंजी
किस स्रोत से आई — एनवायरनमेंट से, या किसी क्रेडेंशियल सेवा से — और कुछ नहीं।

## आश्चर्य से बचाव

| फ़्लैग | असर |
|---|---|
| `--mock` | ऑफ़लाइन mock प्रोवाइडर को बाध्य करें |
| `--json` | stdout पर मशीन-पठनीय आउटपुट; हर टिप्पणी stderr पर |
| `--model` | कॉल किया जाने वाला मॉडल |
| `--endpoint` | भेजने वाले प्रोवाइडर के लिए API रूट |

## डेवलपमेंट

```sh
pnpm install
pnpm --filter jevcore-cli run test
pnpm --filter jevcore-cli run typecheck
```

इस पैकेज के किसी भी टेस्ट को क्रेडेंशियल या सॉकेट की ज़रूरत नहीं। लाइव रूट को एक
एनवायरनमेंट वेरिएबल द्वारा बताए गए स्टब SDK मॉड्यूल के ज़रिए परखा जाता है, इसलिए
डेवलपर की असली कुंजी किसी टेस्ट को नेटवर्क कॉल में नहीं बदल सकती।
